## 1. Decisions this RFC records

These were agreed in discussion before drafting:

| Topic | Decision |
|---|---|
| Tag prefix | `ts-`, matching the `--ts-*` tokens |
| Fonts | Bundle nothing. The README gives a Google Fonts link; the tokens declare font stacks. |
| Framework wrappers | None at v1. Custom elements, plus typings and a documented Vue `isCustomElement` line. |
| Layout editing | ~~Headless.~~ **Amendment A:** `<ts-grid>` ships direct-manipulation editing that works like rearranging an iPhone home screen (§8.6). The core's pure editing operations stay public for hosts that build their own controls, such as an add sheet. |
| Small numbers in dark mode | A `--ts-num-weight` token, with its value set by checking it in the playground |
| Shortfall pattern | CSS stripes mixed from `--ts-loss` with `color-mix()` |
| Passing data | One `data` property per widget |
| Encapsulation | Open shadow DOM, styled through `--ts-*` and `part=` |

The rest of this document was a proposal and is now agreed. Points that were
open are marked **Decided (§12)**; §12 records the outcome.

## 2. Entry points

| Import | Contents | Side effects |
|---|---|---|
| `tickslate` | Core: sizes, placement, layouts, editing operations, formatting, session calendars, widget stats | None |
| `tickslate/elements` | `<ts-grid>` and eight widgets. Exports the classes too. | Registers the elements |
| `tickslate/elements/mini-chart` | `<ts-mini-chart>` | Registers it; imports `emberwick` |
| `tickslate/tokens.css` | The `--ts-*` variables for both themes | Stylesheet |

The mini chart has its own entry so that `tickslate/elements` never imports
Emberwick. Hosts without Emberwick installed are unaffected.

Registration skips a tag that is already defined
(`customElements.get(tag) ?? customElements.define(...)`). Importing the entry
twice, or importing it from two bundles, then doesn't throw.

**Browser baseline:** custom elements, shadow DOM, `ResizeObserver`,
`color-mix()` and `:where()`. In practice that means Chrome 111, Safari 16.2
and Firefox 113 or later. JavaScript syntax targets es2019, as the build
already does.

## 3. Shared conventions

- **Time** is a millisecond epoch (`number`) wherever an instant is meant.
  Calendar days are `'YYYY-MM-DD'` strings in the exchange's local date, so a
  day never shifts with the viewer's time zone.
- **Money and prices** are numbers in major units (rupees, not paise). Numeric
  strings are accepted and converted, as Emberwick does, because Laravel
  serialises decimal columns as strings. Anything else is treated as missing.
- **Vocabulary:** account, strategy, allocation, position, instrument, order,
  fill, session. Broker names are just account names supplied by the host.
- **Everything is plain data.** Layouts, widget data and session specs are
  JSON-serialisable. The only exceptions are the `calendar` object and the
  optional `clock` function described in §7.

## 4. Core: grid and layout

### 4.1 Sizes and breakpoints

```ts
type SizeName = 'S' | 'Wide' | 'Tall' | 'M' | 'L' | 'Banner' | 'XL'

const SIZES: Readonly<Record<SizeName, { cols: number; rows: number }>>
// S 1×1 · Wide 2×1 · Tall 1×2 · M 2×2 · L 3×2 · Banner 4×1 · XL 4×2

function columnsFor(width: number): 2 | 3 | 4
// ≥ 1200 → 4 · 700–1199 → 3 · < 700 → 2

function deviceFor(width: number): 'desktop' | 'phone'
// < 700 → 'phone'. A tablet uses the desktop layout, clamped to 3 columns.

function footprint(
  size: SizeName,
  columns: 2 | 3 | 4,
  supported: readonly SizeName[],
): { cols: number; rows: number; variant: SizeName }
```

`footprint` separates two things the brief's rules mix together:

- the **footprint**: the cells the tile occupies on this grid;
- the **variant**: which of the widget's designed sizes it renders.

| Columns | Footprint | Variant |
|---|---|---|
| 4 | As designed | The requested size |
| 3 | Width becomes `min(cols, 3)` | The requested size, laid out fluidly in the narrower tile |
| 2 | S stays 1×1. Wide becomes 2×1. M becomes 2×2. L and XL become 2×2 when the widget supports M, otherwise 2 × their rows. **Banner** stays full width: 2 × its `phoneRows` (default 1). Tall: see below. | M when L or XL was replaced by M; otherwise the requested size. Banner always keeps its own design. |

**Decided (§12): Tall on phones.** The brief says everything but S goes full width,
which makes Tall 2×2. The *Grid, sizes & reflow* sheet keeps Tall at half
width (1×2), so Capital and Watchlist sit side by side. I propose following
the sheet: both 1-column sizes (S and Tall) stay half width.

**Decided (§12): what width counts.** I propose using the grid element's own width
(via `ResizeObserver`), not the viewport's. That way a host with a sidebar
gets the right column count. The 1200 and 700 thresholds stay as they are.
Hosts that want viewport behaviour can make the grid full width.

**Amendment B (13 Oct 2026): Banner is the always-full-width size.** It
spans every column at every width and keeps its own design, so the year
heat map still shows the whole year on a phone. A widget can give it more
height on phones with `phoneRows` in its catalog entry. The calendar uses
`{ Banner: 2 }`, wrapping the year into two half-year bands; the session
clock keeps one row. This replaces the earlier rule that swapped Banner for M
on phones.

### 4.2 Placement

```ts
interface LayoutItem { id: string; type?: string; size: SizeName }

interface Placement {
  id: string
  col: number   // 0-based
  row: number   // 0-based
  cols: number
  rows: number
  variant: SizeName
}

function place(
  items: readonly LayoutItem[],
  columns: 2 | 3 | 4,
  catalog?: WidgetCatalog,
): { placements: Placement[]; rows: number }
```

Items are placed in array order. Each one goes in the first cell, scanning row
by row from the top left, where its footprint fits. This is the same
algorithm CSS uses for `grid-auto-flow: dense` with auto-placed spans, so the
result matches what CSS would give. The tests check that equivalence.

`<ts-grid>` positions tiles from `place()` instead of relying on `dense`, so
the layout on screen is exactly what the core computes and tests. Hosts that
don't render in a browser get the same positions too. (As built: tiles are
absolutely positioned with the `translate` property, not grid lines. Sliding
a tile is then a compositor-only transition, and `rotate` and `scale` stay
free for the edit-mode wiggle and the lift.)

### 4.3 The widget catalog

```ts
interface WidgetSpec { tag: string; sizes: readonly SizeName[]; label: string; phoneRows?: Partial<Record<SizeName, number>> }
type WidgetCatalog = Readonly<Record<string, WidgetSpec>>

const WIDGETS: WidgetCatalog
// todayPnl, equityCurve, pnlCalendar, edgeStats, capitalFunding,
// openPositions, watchlist, sessionClock, miniChart
```

The core knows tag names only as strings and never touches the DOM. A host
adds its own widgets by spreading `WIDGETS` into a larger catalog. Any element
inside `<ts-grid>` can be a tile. It doesn't have to be a Tickslate widget.

### 4.4 The layout model

```ts
interface Layout {
  version: 1
  device: 'desktop' | 'phone'
  profiles: Record<string, LayoutItem[]>   // 'market' and 'closed' are built in
  topStrip?: string[]                      // phone only, at most 3 item ids
}
```

This is the brief's JSON with one addition: an optional **`type`** on each
item. `id` identifies the tile and `type` names the widget, defaulting to
`id`. The brief's JSON stays valid as written (`{ "id": "todayPnl" }` means
the `todayPnl` widget). A host can also add two of the same widget, such as
`{ "id": "chart-crude", "type": "miniChart", "size": "M" }`.

```ts
function readLayout(input: unknown, options?: {
  catalog?: WidgetCatalog
  device?: 'desktop' | 'phone'
}): { layout: Layout; issues: LayoutIssue[] }

interface LayoutIssue {
  path: string   // e.g. 'profiles.market[3].size'
  code: 'unknown-version' | 'unknown-widget' | 'unsupported-size'
      | 'duplicate-id' | 'bad-shape' | 'top-strip-too-long' | 'top-strip-unknown-id'
  message: string
  fixed: 'dropped' | 'replaced' | 'migrated'
}

const LAYOUT_VERSION: 1
```

`readLayout` is **forgiving and never throws.** Layouts are saved user data,
and a dashboard that refuses to render because of one stale widget is worse
than one that drops the widget and says so. It upgrades older versions,
removes unknown widgets and duplicate ids, and moves an unsupported size to
the nearest size the widget supports. Each fix is reported in `issues`. Input
it can't use at all gives an empty layout with one `bad-shape` issue.

### 4.5 Editing operations (headless)

Each operation is pure and returns a new `LayoutItem[]` without changing its
input:

```ts
function addItem(items, item: LayoutItem): LayoutItem[]           // appended; place() puts it in the first spot it fits
function removeItem(items, id: string): LayoutItem[]
function moveItem(items, id: string, toIndex: number): LayoutItem[]
function resizeItem(items, id: string, size: SizeName, catalog?): LayoutItem[]  // snaps to a supported size
function stepSize(spec: WidgetSpec, current: SizeName, dir: 1 | -1): SizeName   // for size buttons and keyboard resizing
function setTopStrip(layout: Layout, ids: string[]): Layout        // at most 3
```

Two more functions drive live dragging in `<ts-grid>` (§8.6). Both are pure,
so the way tiles shuffle while you drag is decided and tested in the core,
not in DOM code:

```ts
function dropIndex(items, id: string, target: { col: number; row: number },
                   columns: 2 | 3 | 4, catalog?, aspect = 1): number
// The index to move `id` to so that, after place(), its top-left cell lands
// as close as possible to `target` (fractional cells). `aspect` is a column's
// on-screen width over a row's height, so distance is judged as the eye sees
// it. On a tie it keeps the current index, so tiles don't flicker between two
// equally good spots.

function sizeForExtent(spec: WidgetSpec, cols: number, rows: number): SizeName
// The supported size nearest to an extent the user has dragged a resize handle to
```

Drag, resize handles and keyboard editing all end in `moveItem` and
`resizeItem`. A host's add sheet calls `addItem`.

Small helpers added while building the engine: `withProfile(layout, name, items)`
replaces one profile and prunes stale top-strip ids. `emptyLayout(device)`,
`snapSize(size, supported)`, `isSize`, `typeOf(item)`, `SIZE_NAMES` and
`BREAKPOINTS` are exported too.

### 4.6 Saving and loading: the host's side

```js
import { readLayout, deviceFor, WIDGETS } from 'tickslate'

const device = deviceFor(grid.clientWidth)
const saved = await myApi.loadLayout(device)              // the host's storage
const { layout, issues } = readLayout(saved ?? myDefaults[device], { catalog: WIDGETS, device })
if (issues.length) console.info('Layout repaired', issues)
grid.layout = layout

// after an edit
grid.layout = { ...layout, profiles: { ...layout.profiles, market: moveItem(layout.profiles.market, 'watchlist', 0) } }
await myApi.saveLayout(device, grid.layout)               // JSON.stringify-able
```

Tickslate ships no default layouts, because which widgets suit a dashboard is
the host's decision. The playground and README include an example.

## 5. Core: formatting

```ts
interface FormatOptions {
  locale?: string        // e.g. 'en-IN'. Defaults to the runtime's locale.
  currency?: string      // e.g. 'INR'. Without one, money formats as a plain number.
  timeZone?: string      // for times, e.g. 'Asia/Kolkata'
}

function createFormatter(options?: FormatOptions): Formatter

interface Formatter {
  money(v: number, o?: { sign?: 'always' | 'negative'; compact?: boolean; decimals?: number }): string
  number(v: number, o?: { sign?: 'always' | 'negative'; decimals?: number; compact?: boolean }): string
  price(v: number, o?: { decimals?: number }): string          // grouped, no currency symbol
  percent(v: number, o?: { sign?: 'always' | 'negative'; decimals?: number }): string  // v = 0.0123 → '+1.23%'
  time(t: number, o?: { seconds?: boolean }): string           // '11:42', '11:42:20'
  duration(ms: number, o?: { style?: 'clock' | 'words' }): string  // '2:40' · '3h 48m'
  fit(v: number, maxChars: number, o?: { sign?: 'always' | 'negative' }): string  // full form if it fits, else compact
}

function configure(options: FormatOptions): void   // the default for elements with no locale of their own
function currentConfig(): FormatOptions             // as built: what configure() has set
function toNumber(v: unknown): number               // as built: numbers and numeric strings, else NaN
```

- Everything goes through `Intl.NumberFormat` and `Intl.DateTimeFormat`, and
  the formatter caches its `Intl` instances. `en-IN` gives lakh grouping
  (`₹1,52,385.00`) without extra code.
- **Signs.** `sign: 'always'` is the default for money. It uses
  `signDisplay: 'exceptZero'`, then replaces the hyphen-minus with U+2212, so
  you get `+₹1,523.85`, `−₹141.00` and `₹0.00`. Zero carries no sign, as in
  the designs.
- **Compact** forms use the locale's compact notation. **Decided (§12):** for
  `en-IN`, `Intl` gives `+₹1.8K`, `−₹3.3K` and `₹1.8L`, with a capital K, but
  the designs show `+₹1.8k`. I propose keeping `Intl`'s output. Lower-casing
  it would be wrong for other locales and is the kind of special case that
  grows.
- `fit()` lets widgets meet "numbers change in place" without measuring the
  DOM. Each variant declares how many characters its headline holds. When a
  value outgrows that, it switches to the compact form while the tile stays
  the same size. Being a pure function, it's tested in the core.
- `configure()` stores a default and does nothing else. The core still has no
  side effects on import.

## 6. Core: stats helpers

Some widgets show figures derived from series the host already has. The core
exports the calculations, so hosts that want the numbers elsewhere get the
same results the widgets show.

```ts
interface DayResult { date: string; pnl: number; trades?: number }   // 'YYYY-MM-DD'

function equitySeries(days: readonly DayResult[]): Array<{ date: string; equity: number; peak: number; drawdown: number }>
function equityStats(days: readonly DayResult[]): { net: number; peak: number; maxDrawdown: number; tradingDays: number; trades: number }
function dayStats(days: readonly DayResult[]): { net: number; greenDays: number; redDays: number; greenRate: number; best: number; worst: number }

interface TradeResult { pnl: number; holdMs?: number }
function edgeStats(trades: readonly TradeResult[]): EdgeStats       // the shape §8.4 takes
function histogram(values: readonly number[], edges: readonly number[]): Array<{ from: number; to: number; count: number }>

function funding(account: FundingAccount): FundedAccount           // §8.5
```

`edgeStats` handles the edge cases explicitly. With no losses, profit factor
is `Infinity` and displays as `∞`. With no trades, each stat is `null` and
displays as `—`.

## 7. Core: session calendars

```ts
interface SessionSpec {
  id: string                       // 'nse', 'mcx'
  label: string                    // 'NSE', 'MCX'
  timeZone: string                 // 'Asia/Kolkata'
  days: readonly number[]          // ISO weekdays, 1 = Monday
  open: string                     // 'HH:MM' local
  close: string | { default: string; ranges: ReadonlyArray<{ from: string; to: string; close: string }> }
  // a fixed close, or date ranges with their own close (MCX's seasonal close)
  specialSessions?: Record<string, { open: string; close: string }>  // e.g. a weekend special session
}

interface CalendarInput {
  sessions: readonly SessionSpec[]
  holidays?: Record<string, readonly string[]>   // session id → 'YYYY-MM-DD'[]; '*' applies to all
}

function createCalendar(input: CalendarInput): Calendar

interface Calendar {
  state(sessionId: string, now: number): {
    open: boolean
    opensAt: number | null     // next open, when closed
    closesAt: number | null    // when open
    startedAt: number | null   // when open
    progress: number | null    // 0..1 through the session, when open
  }
  isTradingDay(sessionId: string, date: string): boolean
  nextChange(sessionId: string, now: number): { at: number; to: 'open' | 'closed' }
  candleClose(sessionId: string, now: number, timeframeMinutes: number): number | null
  // the next candle close, aligned to the session open (NSE 5m candles close at 09:20, 09:25, …)
  // As built, also: sessions (the ids), session(id), hours(id, date) → { open, close } | null,
  // and windows(id, from, to), which the profile schedule and session-clock lanes use.
}

// As built, after checking circulars on 13 Oct 2026 (NSE F&O now closes at 15:40):
const presets: {
  nse(options?: { segment?: 'equity' | 'derivatives' }): SessionSpec
  // 'equity' → 'nse' 09:15–15:30; 'derivatives' → 'nse-fo' 09:15–15:40 (15:30 before 3 Aug 2026)
  mcx(options?: { segment?: 'international' | 'cotton' | 'agri'; years?: number[] }): SessionSpec
  // 'international' → 'mcx' 09:00–23:30 during US daylight saving, else 23:55;
  // 'cotton' → 09:00–21:00; 'agri' → 09:00–17:00. years default to last, this and next.
}
```

- **Holidays are an input.** The calendar ships no holiday lists, because they
  change every year and the host owns that data source.
- **Wall-clock time without dependencies:** `Intl.DateTimeFormat` with
  `timeZone` converts between instants and exchange-local times, the same
  approach for any exchange.
- **MCX's close** changes with US daylight saving. `presets.mcx` works out
  those dates for the given years with `Intl`, using `America/New_York`
  offsets, and returns ordinary date ranges. The rule then lives in a preset,
  not inside the calendar logic. **Before task 3, I'll check the hours of both
  presets against current exchange circulars, as the brief asks.**
- The candle-close countdown takes the idea from Emberwick 0.14, not its code.

### 7.1 Choosing the layout profile

```ts
interface ProfileSchedule {
  market: { sessions: string[]; leadMinutes?: number; lagMinutes?: number }
  // 'market' while any listed session is open, widened by lead and lag; 'closed' otherwise
}

function activeProfile(calendar: Calendar, schedule: ProfileSchedule, now: number): 'market' | 'closed'
function nextProfileChange(calendar: Calendar, schedule: ProfileSchedule, now: number): number
```

The Traed spec runs market hours from 09:00 to 15:35, which is NSE widened by
15 minutes before the open and 5 after the close. It also asks whether a live
MCX strategy should keep the market layout until 23:30. With this schedule,
both are host settings: `{ sessions: ['nse'], leadMinutes: 15, lagMinutes: 5 }`,
with or without `'mcx'`.

## 8. Elements

### 8.1 What every widget shares

| Member | Kind | Meaning |
|---|---|---|
| `data` | property | The widget's data (shapes below). Setting it updates text and shapes in place; the DOM is not rebuilt. `null` shows an empty state. |
| `size` | attribute and property | The designed size to render. `<ts-grid>` sets it. Standalone, the host sets it. An unsupported size snaps to the nearest supported one. |
| `variant` | read-only property | The size actually rendered after phone reflow (§4.1) |
| `label` | attribute | Replaces the default heading and accessible name |
| `locale`, `currency`, `time-zone` | attributes | Formatting. If absent, they come from the nearest `<ts-grid>`, then from `configure()`. |
| `actions` | property | The action buttons the widget may show (§8.3). Defaults to none. |

- **Shadow DOM:** open. The tile is a `<section aria-label="…">` with
  `part="tile"`. Other parts are `header`, `label`, `value` and `chart`.
- **Tile size:** inside a grid, the widget fills its cell. Standalone, it
  takes the host's width and a height of `rows × --ts-row + (rows − 1) × --ts-gap`.
- **Updates never move the grid.** The tile size depends only on the layout.
  Inside, figures use `font-variant-numeric: tabular-nums lining-nums`, and
  `fit()` (§5) keeps long values within their slot.
- **Freshness:** every data shape takes an optional `asOf` (ms) and `live`
  (boolean). `live` shows the pulsing dot, which is static under
  `prefers-reduced-motion`. `asOf` shows "synced …" where the design has it.
- **Internal structure:** each widget is split into a pure
  `viewModel(data, variant, formatter)` function and a thin DOM renderer. The
  view models live outside the DOM code, so `node --test` covers them without
  a DOM, and CI stays dependency-free.

**As built (`TsWidget`, `src/elements/widget.js`):**

- A widget is a template, a pure `viewModel(data, variant, ctx)` and an
  `update(vm, variant)`. `ctx` is `{ fmt, now, label }` plus whatever the
  element's `viewContext()` returns (the equity curve passes its `range`), not
  the bare formatter above. A view model that throws shows the empty state.
- `clock` (`() => number`, default `Date.now`) is on every widget, not only the
  session clock, and feeds `ctx.now`. Tests and demos freeze time with it.
- `every(ms)` re-renders on a timer while the element is connected and the page
  is visible, and again at once when the page becomes visible. `every(0)` stops it.
- `upgrade(...names)` re-applies properties set before the element was defined.
  The base does this for `data`, `size` and `clock`; a subclass lists its own.
- Headline figures scale with the tile (`container-type: inline-size` and
  `cqi` units, capped at the design size), so the 170px phone S and the 351px
  phone Wide fit without a separate layout. Desktop sizes are unaffected.
- Not built yet: the `actions` property (§8.3) and the `header`, `label` and
  `value` parts. The tile is `part="tile"`; Today's P&L adds `part="chart"`.

### 8.2 Events

All events are `CustomEvent`s that bubble and are `composed`, so they cross
shadow roots.

| Event | From | `detail` |
|---|---|---|
| `ts-action` | widgets | `{ action: string; id?: string; value?: string }` (§8.3) |
| `ts-columns-change` | `<ts-grid>` | `{ columns: 2 \| 3 \| 4; device: 'desktop' \| 'phone' }` |
| `ts-profile-change` | `<ts-grid>` | `{ profile: string; reason: 'schedule' \| 'override' \| 'override-ended' }` |
| `ts-layout-issues` | `<ts-grid>` | `{ issues: LayoutIssue[] }`, when a layout it was given needed repairs |
| `ts-edit-change` | `<ts-grid>` | `{ editing: boolean }` |
| `ts-layout-change` | `<ts-grid>` | `{ layout: Layout; profile: string; reason: 'move' \| 'resize' \| 'remove'; id: string }`, after the user commits an edit. The host saves `layout`. |

### 8.3 Actions are requests, never effects

The designs have buttons for Exit, Exit all, Rebalance, Add instrument, chart
timeframes and equity ranges. "Data in, nothing out" means a widget never
carries these out. It dispatches `ts-action`, and the host decides what
happens, including the confirmation the Traed spec requires before exiting a
position.

Buttons that act on the outside world are **off by default**. A host turns
them on with `el.actions = ['exit-position', 'exit-all']`. A host that hasn't
wired an Exit handler then never shows an Exit button that does nothing.
Controls that only change what the widget shows are always on: the equity
range, the chart timeframe and the calendar span.

### 8.4 `<ts-grid>`

```html
<ts-grid locale="en-IN" currency="INR" time-zone="Asia/Kolkata">
  <ts-today-pnl item="todayPnl"></ts-today-pnl>
  <ts-session-clock item="sessionClock"></ts-session-clock>
  <ts-watchlist item="watchlist"></ts-watchlist>
</ts-grid>
```

| Member | Kind | Meaning |
|---|---|---|
| `layout` | property | A `Layout` (§4.4). The grid runs it through `readLayout` itself and fires `ts-layout-issues` if anything was repaired. |
| `profile` | attribute | Pins a profile. When absent, the schedule decides. |
| `schedule` | property | `{ calendar, ...ProfileSchedule }`. When set and `profile` is absent, the grid switches profiles on time, using one timer set to `nextProfileChange`. *Arrives with the session calendar (task 3).* |
| `override(profile)` | method | *Arrives with the session calendar (task 3).* Switches until the next scheduled change, then fires `ts-profile-change` with `reason: 'override-ended'`. This is the Traed spec's manual switch. |
| `editing` | attribute | Edit mode (§8.6). The host toggles it from its own Edit and Done buttons; the grid also sets it on a long press and clears it on Escape. |
| `columns` | read-only property | Current column count |
| `catalog` | property | Defaults to `WIDGETS`. Hosts with custom tiles pass a larger catalog. |

- **Children are the host's.** The host renders widget elements, binds their
  `data` with its own framework, and tags each one with `item="<layout id>"`.
  The grid positions the children in the active profile, hides the others,
  and sets their `size`. Layout items with no matching child are skipped in
  placement, so they leave no hole. Children with no matching item stay
  hidden.
- Hosts may render only the active profile's children, using
  `ts-profile-change`, or render all of them. Either works.
- **Top strip.** At 2 columns, the children named in `layout.topStrip` render
  in a pinned row above the grid (`position: sticky`), at most three.
  **Decided (§12):** is the top strip in v1? It's in the layout model but not in the
  brief's v1 list. My proposal is to support it in the model and the core now,
  and render it in the grid in v1 only if you say so.

### 8.5 The v1 widgets

Shapes are written in TypeScript notation. `Money` is a number (or numeric
string) in major units. `asOf` and `live` (§8.1) are allowed on every shape
and are left out below.

#### 1. Today's P&L: `<ts-today-pnl>`, sizes S · Wide · M

```ts
{
  net: Money            // shown as given; the widget doesn't recalculate it
  realized: Money
  unrealized: Money
  fees: Money
  closedCount?: number
  openCount?: number
  intraday?: Array<{ t: number; v: Money }>                  // M: the curve
  marks?: Array<{ t: number; kind: 'entry' | 'exit'; label?: string }>
  window?: { from: number; to: number }                      // M: the x-axis, e.g. the session from calendar.state()
}
```

M's "low −₹640 at 09:45" is derived from `intraday`. The chart's accessible
label states the result: "Intraday P&L: low −₹640, now +₹1,523.85".

**As built:** S's heading is "Today", because "Today's P&L" does not fit a
narrow tile; a host `label` replaces the heading on Wide and M, and the accessible
name on every size. `net` is shown exactly as given and goes compact through
`fit()` when it is too long. Fees always read as a deduction, whichever way the
host signs them. `asOf` shows as a time (S top right, Wide in the note under the
headline). M's summary line gives the low and the high ("low −₹801 at 09:30 · high
now"). The middle axis label is the round time (30, else 15 minutes) nearest the
window's middle. With fewer than two readings the chart says "No intraday data
yet" instead of drawing a line, and a mark outside the readings is left out.

#### 2. Equity curve: `<ts-equity-curve>`, sizes Wide · M · XL

```ts
{
  days: DayResult[]     // the daily P&L series, ascending; the widget accumulates it (equitySeries)
  fees?: Money          // M, XL
  trades?: number       // XL "21 · 66 trades"
}
```

Attribute `range="1W|1M|3M|YTD|All"` (default `All`) filters the series in
the widget. XL's range buttons change it and fire
`ts-action { action: 'range', value }`. XL shades the drawdown below the
running peak.

**As built:** ranges count back from the latest date in the data, not from the
clock, so a series that ends last Friday still has a "last month". 1W is the 7
calendar days ending on that date. 1M and 3M go back whole calendar months and
clamp at month end (31 March back one month is 28 or 29 February). YTD starts on 1
January of the latest date's year. Equity inside a range starts at 0 on its first
day: it is the P&L made over the range, so Peak is never below 0. `fees` and
`trades` describe the host's whole series, so they show only when the range keeps
every day; otherwise Trades falls back to the sum of `days[].trades`, or "—".
XL always shows the range buttons; pressing one sets `range` itself, then fires
`ts-action`. Wide's heading reads "Equity · 60 days". Only XL draws the drawdown
band and the peak line.

#### 3. Daily P&L calendar: `<ts-pnl-calendar>`, sizes Tall · M · Banner

```ts
{
  days: DayResult[]     // the same shape as the equity curve, so one series feeds both
  today?: string        // 'YYYY-MM-DD'; later days are drawn as upcoming
}
```

Tall shows 6 weeks, M a quarter (13 weeks) and Banner a year, at every width; on phones the year wraps into two half-year bands (amendment B). Rows are Monday
to Friday. A day with no entry shows as "no trades", drawn in `--ts-surface-2`.
Cell strength keeps Traed's formula, 0.22 + 0.78 × |pnl| ÷ the largest |pnl|
in view, mixed from `--ts-profit` or `--ts-loss`. A weekend entry (a special
session) counts in the totals but has no cell.

#### 4. Edge stats: `<ts-edge-stats>`, sizes S · Wide · M

```ts
interface EdgeStats {
  trades: number
  wins: number
  losses: number
  winRate: number | null       // 0..1
  profitFactor: number | null
  avgWin: Money | null
  avgLoss: Money | null        // a negative number
  expectancy: Money | null     // per trade
  avgHoldMs?: number | null
}
{ stats: EdgeStats; scope?: string; distribution?: Array<{ label: string; count: number; sign: 1 | -1 }> }
```

`edgeStats(trades)` in the core produces `stats`. S shows a single stat,
chosen with `stat="win-rate|profit-factor|avg-win-loss|expectancy"` (default
`win-rate`). M's histogram is `distribution`, which `histogram()` can build.

#### 5. Capital funding: `<ts-capital-funding>`, sizes S · Tall · L

```ts
interface FundingAccount {
  id: string
  name: string                       // 'Groww', 'Kite'
  balance: Money
  allocations: Array<{
    id: string
    name: string                     // the strategy
    detail?: string                  // 'NIFTY 50 · 5m'
    amount: Money
    live?: boolean
    pnl?: Money                      // L: shown on the row
    funded?: Money                   // optional: the host's own funded amount, which overrides the rule below
  }>
}
{ accounts: FundingAccount[] }
```

The widget derives allocated, free, shortfall and the funded share for each
account with `funding()`. Shortfalls get the stripe pattern as well as the
colour. Rebalance is an action (`ts-action { action: 'rebalance', id }`).

**Decided (§12): how allocations draw on the balance.** The designs show Kite
(₹22,895.20 against two ₹30,000 allocations) with *each* allocation short
₹7,104.80. That is each one measured alone against the whole balance. The two
rules are:

- **Independent:** each allocation is funded if the balance alone covers it.
  This matches the designs, but it says two strategies are each nearly funded
  by money that can only be spent once.
- **In order** (proposed): allocations draw down the balance in array order.
  The first gets ₹22,895.20 and is short ₹7,104.80; the second gets nothing
  and is short ₹30,000.

Either way, a host that knows better can pass `funded` for each allocation.

#### 8. Session clock: `<ts-session-clock>`, sizes S · Banner

```ts
{
  calendar: Calendar                 // from createCalendar()
  sessions: string[]                 // lanes, e.g. ['nse', 'mcx']; S shows the first
  timeframes?: number[]              // Banner: candle-close ticks, e.g. [5, 15]
}
```

This is the one widget that ticks on its own: once a second for the Banner,
once a minute for S. It pauses while hidden (`visibilitychange`) or
disconnected. A `clock` property (`() => number`, default `Date.now`) lets the
playground and tests freeze it at a fixed time. It needs no fetching, so it
stays within "data in, nothing out".

**As built:** it ticks once a second at both sizes (the open/closed flip and the
countdown must be on time, and a tick that only sets text is cheap). Times are
shown in the first session's zone, so every lane reads against one clock. S's
heading is "Market open" or "Market closed" and shortens to "Open" or "Closed"
at phone width. Banner draws ticks for the first two timeframes only: thin ticks
(the first timeframe) only for the next hour of an open lane, thick ticks (the
second) across the session but only where they sit at least 6px apart on the rail
as it is now. A missing calendar or an unknown session id shows as a muted
message in its lane, not an error.

#### 9. Mini chart: `<ts-mini-chart>`, sizes M · L · XL (`tickslate/elements/mini-chart`)

```ts
{
  charts: Array<{
    id: string
    instrument: string
    timeframe?: string               // '5m'
    bars: EmberwickBar[]             // Emberwick's bar shape, ascending by time
    marks?: Array<{ t: number; kind: 'entry' | 'exit'; label?: string }>
    changePct?: number
    note?: string                    // XL: '2 strategies · 1 in position'
  }>
  countdown?: boolean                // candle-close countdown on the last price
  volumeProfile?: boolean            // L
}
```

- M and L show `charts[0]`. XL shows the first two side by side.
- **Live updates without redrawing everything:** when new `data` arrives, the
  widget compares bars by time. If only the newest bar changed or new bars
  were appended, it updates the chart incrementally; otherwise it calls
  `setData`. Hosts can then simply reassign `data` from Vue or React state
  every tick.
- The theme maps `--ts-*` onto Emberwick's theme options and re-reads them
  when `data-theme`, `.dark` or the colour scheme changes.
- The L timeframe buttons send `ts-action { action: 'timeframe', id, value: '15m' }`,
  because the host supplies the bars.
- **Peer dependency:** `emberwick >= 0.14` (countdown and volume profile).
  The published `package.lib.json` in the Emberwick checkout says 0.12.0. Is
  0.14 released, or should v1 ask for less?

### 8.6 Editing the layout (amendment A)

The model is rearranging apps on an iPhone. You pick a tile up and drag it.
The other tiles slide out of its way while you move. You let go, and it
settles into the gap. Nothing jumps, and nothing waits for a save button.

**Entering and leaving edit mode**

- **Long press** a tile for 500 ms without moving more than 8 px. This works
  with touch, pen or mouse. The grid enters edit mode, and the tile you're
  holding is already picked up, so one gesture both starts editing and starts
  the drag, as on iOS.
- The host can also set `editing` from its own Edit button.
- Leave edit mode with Escape, by tapping empty grid space, or when the host
  removes `editing` (its Done button). Each change fires `ts-edit-change`.

**In edit mode**

- Tiles **wiggle** gently (±0.8°, each tile out of phase with the next).
  Under `prefers-reduced-motion` there is no wiggle; tiles get a dashed
  outline instead.
- Each tile shows a **remove** badge at its top left and a **resize** handle
  at its bottom right. Both are at least 44 px on touch.
- Widget content stops receiving pointer events, so a drag can never press a
  widget's own button or link.

**Dragging**

- **Pick up:** with a mouse, after 4 px of movement. With touch, after a
  200 ms hold. A quick swipe still scrolls the page in edit mode, because a
  dashboard scrolls vertically and fills the screen with tiles. On a long
  press outside edit mode, the pick-up is immediate.
- **Lift:** the tile scales to 1.04, gains a deeper shadow and rises above
  the others. It follows the pointer with no lag, because only `transform`
  changes, once per animation frame.
- **Live reflow:** the core's `dropIndex()` picks the slot nearest the tile's
  top-left corner. The tiles slide to their new places over 220 ms with an
  ease-out curve; FLIP animation keeps this to `transform` only. A
  soft-outlined placeholder shows where the tile will land. The slot only
  changes after the pointer has rested on a new spot for 120 ms, so sweeping
  across the grid doesn't set off a cascade of moves.
- **Auto-scroll:** within 64 px of the scroll container's top or bottom edge,
  the page scrolls faster the closer the pointer gets.
- **Drop:** the tile glides from the pointer into its slot. Then the grid
  commits the move and fires `ts-layout-change` with `reason: 'move'`.
  Dropping where it started fires nothing.
- **Cancel** (Escape, or the browser cancelling the pointer): the tile glides
  back, and the order is unchanged.
- **Haptics:** `navigator.vibrate(8)` on pick-up where the browser supports
  it (Android). iOS Safari has no web haptics API.

**Resizing**

- Drag the handle and the outline snaps through the sizes the widget
  supports (`sizeForExtent`). The other tiles reflow live, as they do in a
  drag. Release to commit (`reason: 'resize'`).
- Tapping the handle without dragging steps to the next size (`stepSize`).

**Removing.** Tapping the badge shrinks and fades the tile out (180 ms), the
gap closes, and the grid fires `ts-layout-change` with `reason: 'remove'`.
There is no confirmation dialog, because the host's add sheet puts a widget
back. A host that wants an undo toast has everything it needs in the event.

**Adding.** The host calls `addItem` and sets `layout`. The new tile scales
in from 0.92 and fades in, at the first spot where it fits.

**Keyboard and screen readers**

- In edit mode, tiles are focusable.
- Space or Enter picks a tile up, the arrow keys move it one cell (with the
  same live reflow), and Space or Enter drops it. Escape cancels the move.
- `+` and `−` change the size. Delete removes the tile.
- Moves are announced in a polite live region, for example "Watchlist, moved
  to position 3 of 10". Unlike ticking prices, these are announcements the
  user caused, so `aria-live` is appropriate here.

**Phones** use the same drag model. This replaces the brief's list-based
editor, which assumed tile dragging was too fiddly on a small screen. iOS
shows it works with a long press and live reflow. The top strip is
rearranged in the same way, within its own row.

**Performance budget:** 60 fps with 30 tiles on a mid-range phone. `dropIndex`
takes under 1 ms for 30 tiles (checked by a test). No layout reads happen
during a drag apart from one cached measurement of the grid at pick-up.

## 9. Theming

- Theming uses CSS variables only. `tickslate/tokens.css` sets them on
  `:root` with zero specificity. CSS custom properties pass through shadow
  roots, so a host overrides any `--ts-*` with an ordinary selector.
- Dark mode applies with `data-theme="dark"`, a `.dark` ancestor (Tailwind),
  or the OS setting unless `data-theme="light"` is set. That's how the tokens
  file already works.
- **New tokens** this RFC adds:

| Token | Default (light / dark) | Purpose |
|---|---|---|
| `--ts-num-weight` | 500 / 500 | Weight for figures 14px and up |
| `--ts-num-weight-small` | 500 / 600 (to be checked) | Weight for figures below 14px (open question 5) |
| `--ts-pad` | 18px / 16px | Padding inside a tile (the dark designs are tighter) |
| `--ts-gap-compact` | 10px | The gap at 2 columns |
| `--ts-row-compact` | 150px | Row height at 2 columns |

- **Phone row height.** The Traed spec has phone rows at auto height with a
  120px minimum. The brief uses 150px rows everywhere. Auto rows would let
  content resize tiles, which breaks "updates never move the grid", so I
  propose a fixed `--ts-row-compact` that hosts can lower.
- **Tabular figures.** Production Type's Newsreader page lists tabular
  figures, but I couldn't confirm the Google Fonts build keeps the `tnum`
  feature. Task 4's playground will measure digit widths with tabular-nums on.
  If they differ, the fallback is a `--ts-font-num-tabular` stack for live
  figures, decided then.

## 10. Locale and framework usage

```js
// once, at start-up
import { configure } from 'tickslate'
configure({ locale: 'en-IN', currency: 'INR', timeZone: 'Asia/Kolkata' })
```

Or per grid, with `<ts-grid locale currency time-zone>`, or per widget.

- **Vue 3:** `compilerOptions.isCustomElement = (tag) => tag.startsWith('ts-')`.
  Bind data with `:data="pnl"`. Vue sets it as a property because the element
  defines one.
- **React 19:** `<ts-today-pnl data={pnl} />` sets the property natively.
  For events, use a `ref` and `addEventListener('ts-action', …)`. The README
  will show both patterns.
- **Types:** `tickslate/elements` augments `HTMLElementTagNameMap` with every
  tag. The README gives a short snippet for typing them in JSX.

## 11. Accessibility

- Each widget is a labelled region: `<section aria-label>`, and the label
  includes the headline result ("Today's P&L, +₹1,523.85").
- Charts have `role="img"` and a label that states the result, built by the
  view model. Calendar cells carry their date and value in their own labels.
- Gains and losses always carry a sign. Shortfalls always have stripes as well
  as colour.
- Ticking values get **no `aria-live`**, which would flood screen readers once
  a second. Labels change, but nothing is announced.
- Action buttons are real `<button>`s with at least 44px touch targets at 2
  columns.
- `prefers-reduced-motion` stops the live dot's pulse and value transitions.

## 12. Decisions

All ten proposals were accepted on 13 Oct 2026.

| # | Question | Decision |
|---|---|---|
| 1 | Tall on phones: 1×2 (the design sheet) or 2×2 (the brief)? | 1×2 |
| 2 | Breakpoints from the grid's own width or the viewport's? | The grid's own width |
