### Added

- `<ts-mini-chart>`: a small candlestick chart with entry and exit marks and a candle-close countdown, at `M`, `L` and `XL`, drawn by Emberwick. Import it from `tickslate/elements/mini-chart`; `tickslate/elements` and the CDN files never load it.
- `emberwick` (0.14.0 or later) is an optional peer dependency, loaded the first time the chart has bars. Without it the tile shows "The chart library isn't installed" and the rest of the page is untouched.
- `<ts-mini-chart>` updates in place: the same bars do nothing, a changed last candle is one Emberwick `update`, a closing candle is one `update` and one `append`, and anything else is a `setData`.
- The chart follows your theme: the `--ts-*` tokens (candles from `--ts-profit` and `--ts-loss`) are read when it is made and again whenever one resolves differently, wherever the theme is set (`data-theme`, `class`, `data-ts-theme`, `data-ts-palette` or an inline token on `<html>`, a wrapper, the grid, `<body>` or the widget), on the system colour scheme and on each data update. Reduced motion is followed while the page is open.
- `volumeProfile` (L) takes Emberwick's own `ProfileData`, which you compute; a profile Emberwick rejects, or one whose `version` is not 1, shows "The volume profile couldn't be drawn".
- A `timeframe` action (`ts-action` with `id` and `value`) for the timeframe buttons at `L`, offered with `actions = ['timeframe']`.
- While Emberwick is still loading, the chart's box shows a skeleton and the tile is `aria-busy`. The tile's group is named by the label and the headline, and each chart's box carries the full summary.
- Types `TsMiniChart` (declared for `tickslate/elements/mini-chart` only), `MiniChartData`, `MiniChartBar`, `MiniChartProfile`, `MiniChartModel` and `TsMiniChartAction`, and the `miniChart.*` messages.

### Internal

- `scripts/verify-package.mjs` proves that importing `tickslate`, `tickslate/elements` or a CDN file never imports or names `emberwick`, that no shared chunk carries it, that `tickslate/elements/mini-chart` imports it only lazily and as an external, that the optional peer stays at `>=0.14.0`, and that `tickslate/elements` bundles with esbuild with Emberwick not installed. `scripts/pack-lib.mjs` refuses a `package.lib.json` that makes it anything but an optional peer. `vite.lib.config.js` and `vite.dev.config.js` keep `emberwick/profiles` external too.
- `emberwick` 0.14.2 is a dev dependency, for the browser spec and the gallery fixture only; the unit suite stays install-free and uses a fake Emberwick.
- The size budget of the new entry is 29 kB (measured 26,800 B min+gz on the integrate/0.3.0 base, Emberwick not counted). The `miniChart.*` messages add about 215 to 220 B min+gz to every entry through the shared core.
- Deviations from RFC 0004 §6: `volumeProfile` is typed by `MiniChartProfile`, a structural copy of Emberwick's `ProfileData`, so the declarations resolve without the optional peer installed; the summary is built from `miniChart.head`, `miniChart.last`, `miniChart.bars`, `miniChart.join`, `miniChart.pair` and `miniChart.flat` (added beside the RFC's keys) so a missing timeframe or change and a single bar still read as a sentence; the message check accepts a camelCase first segment (`miniChart.*`); the box Emberwick draws in has `tabindex="-1"` because Emberwick otherwise makes it a tab stop inside `aria-hidden`.
- Widens RFC 0004 §6.4's observation scope (`<html>` and the nearest grid) to match docs/theming.md, which lets a host set the theme on the grid or the widget, "any element": one `MutationObserver` on `<html>` with `subtree` and an attribute filter (now including `style`) is shared by every mini chart, wakes a chart only for a change on it or an ancestor, and calls `setTheme` only when a mapped value changed; every data render re-reads too.
- `TsMiniChart` is declared in `src/elements/mini-chart.d.ts`, and shipped as `mini-chart.d.ts`, rather than in `elements.d.ts`, so `tickslate/elements` declares nothing its runtime lacks (RFC 0004 §6.1); `elements.d.ts` imports it as a type for the tag map only. `test/manifest.test.mjs` copies that file beside the others.
- Further deviations from RFC 0004 §6: the volume profile is drawn at `L` only (the RFC's data comment says L); an `XL` chart on a tile narrower than about 560 px stacks its two charts; bars that become empty empty the chart (`setData([])`) rather than destroy it; a profile is keyed by its figures (version, step, sessions, and bin count and checksums), so an equal re-sent profile is no change.
- `verify-package`'s "bundles without the peer" checks build with `preserveSymlinks` and no `external`, so the scratch consumer cannot reach the repo's `node_modules/emberwick`; a probe fails the run if it can, and a planted static import in `elements.js` fails the production bundle.
