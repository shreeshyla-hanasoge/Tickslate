### Added

- `readLayout` caps a layout: 100 items per profile, 20 profiles (the built-in `market` and `closed` always count and are read first) and 128-character ids. What is over a cap is dropped and reported as `too-many-items`, `too-many-profiles` or `bad-shape` in `ts-layout-issues`. `topStrip` is read up to 32 entries (more is `too-many-items` at the path `topStrip`). `readLayout` also never throws for input that is not JSON: a throwing getter or Proxy gives an empty layout and one `bad-shape` issue. A direct `readLayout` call can pass `maxItems` and `maxProfiles` (a positive integer or `Infinity`); `<ts-grid>` and `persistLayout` never do.

### Changed

- A layout from storage or the network with more than 100 items in a profile, more than 20 profiles, or an id over 128 characters now loses the excess instead of drawing it.

### Internal

- `readLayout` keeps the input's profile order (the caps pick which profiles are read first, but they are read and returned in input order), proved by `test/layout-determinism.test.mjs`: 3,000 seeded valid layouts, with and without options, serialise byte for byte like a frozen copy of the pre-cap reader. The fuzz file gained a million-entry `topStrip` timing case and cases for cycles, 200,000-level nesting, throwing getters, Proxies and `null` options.
- Lint: the browser globals are declared so `no-implied-eval` sees `setTimeout('…')`, `setInterval('…')` and `window.setTimeout('…')`; `no-restricted-syntax` names `srcdoc`, computed `['innerHTML']`/`['outerHTML']`/`['srcdoc']`, `write`, `writeln`, `parseHTMLUnsafe` and computed markup-sink calls in `src/elements`; `.mjs` files are covered. Each was planted in a scratch copy and fails the lint.
- `release.yml` installs npm 11 in the publish job (trusted publishing needs 11.5.1 or later); `pages.yml` grants `pages: write` and `id-token: write` to the deploy job only. The dry-run step cannot be shown to pass without dispatching the workflow, which only the maintainer does.
- Deviation: the strip cap reads 32 entries rather than `TOP_STRIP_MAX` (3), so each surplus entry is still reported as `top-strip-too-long` and a bad entry in front does not hide a good one.

- Seeded fuzz test (`test/layout-fuzz.test.mjs`, mulberry32): 10,000 random values go to `readLayout` with and without options; it never throws, the result is always a valid layout inside the caps, and each call is timed against a 5 ms ceiling. The seed is in every failure message. The same file tests the 100/101, 20/21 and 128/129 boundaries and the two options.
- XSS spec (`test/browser/xss.spec.mjs`, fixture `xss.html`, all five projects): six payloads (an `img` with `onerror`, a quote-closing `svg onload`, a `</style>` breakout, a `javascript:` URL, an entity-encoded form and one with a null byte) go into every widget data string, the `label` and `aria-label` attributes, every built-in message (as `messages` overrides), layout item ids, catalog label, description and category, a `ts-add-request` id, session labels, chart categories and series names, and the persist key. The page is drawn, put in edit mode, the picker opened, a table sorted and a chart hovered. The spec asserts that nothing ran, that no `img`, `script`, `iframe`, `on*` attribute or `javascript:` URL exists in the document or any shadow root, that nothing requested the payload's image, and that the payload is on the page as text. It runs plain and again under the strict CSP and Trusted Types of RFC 0003 §14. A planted `innerHTML` write in `metric.js` makes it fail in both. No widget failed.
- `npm run lint` (ESLint 9.39.5 and `eslint-plugin-no-unsanitized` 4.1.5, exact devDependencies; the maintainer approved the install): `no-unsanitized/property` and `/method` for `src/elements`, `no-eval`, `no-implied-eval` and `no-new-func` for `src`. `escapeHtml` is the accepted escaper. The one named override is `src/elements/html.js`, the library's sink, whose four writes are module-constant markup (through the `tickslate` policy) or the node tests' no-DOM fallback. `lint` is its own CI job.
- Dependabot (weekly; npm with minor and patch updates grouped, github-actions; labelled `dependencies`), a CodeQL workflow for `javascript-typescript` (push to `master`, pull requests, weekly; `build-mode: none`) and every `uses:` in every workflow pinned to a full commit SHA with the tag in a comment, all resolved with `gh api`. `ci.yml` gained `permissions: contents: read`. `test/workflows.test.mjs` checks the pins, the permissions and the release workflow's shape without a YAML parser.
- `.github/workflows/release.yml`: `workflow_dispatch` only, `master` only, `dry-run` true by default; the publish job needs the maintainer's approval of the `npm-release` environment and runs `npm publish ./dist-lib --provenance --access public`. It never tags or creates a release. It has not been run and no agent runs it. `docs/RELEASING.md` describes it and keeps the by-hand steps; `SECURITY.md` lists the protections.
- Deviations from RFC 0004 §8: the fuzz test's 5 ms ceiling is measured with up to two re-timings of a slow call (fails only if every attempt is over), because a single garbage-collection pause on a busy runner measured 4.4 ms for a call that takes microseconds; `test/workflows.test.mjs` is a file the RFC did not list; the document scan covers `document.body` only, since the fixture's own `<head>` holds scripts, meta and link by design; `maxProfiles` counts the two built-in profiles (so 18 others fit under the default 20), as the RFC's "always count".
