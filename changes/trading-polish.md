### Added

- `width` on a `<ts-table>` column: `'content'` (as wide as its widest text, up to half the table, a cut cell ending in an ellipsis with its text as its `title`), `'fill'`, or a number of CSS pixels (at least 40). Unset keeps the equal share, so a table that sets none renders as before; the priority-drop rule is unchanged.
- `configure({ clock })`: one clock for the page. Every grid and widget without a `clock` of its own reads it, `null` returns to `Date.now()`, and `currentConfig()` returns it. Calling `configure()` again after the time it returns has moved draws every tile and runs every grid's schedule again. `createCalendar` takes its default `now` from it, so a pretend clock also makes `calendar.issues` deterministic.

### Changed

- With the `persist` attribute (or `persistLayout()`), a layout the host assigns to `grid.layout` after the grid connects, and before the user's first edit on that device, is now the device's defaults: a saved layout still wins over it, with nothing saved it stays on screen, and `reset()` returns to it. Before, `reset()` returned to the layout the grid started with. The order of events is in the saving-layouts guide.
- A tile heading too narrow for its label ends in an ellipsis and carries the full label as its `title`; the DOM text and the accessible name were always the whole label.
- `configure({ clock })` given anything but a function or `null` keeps the clock already set. `persistLayout()` with no `defaults` takes the grid's layout at attach as the defaults, so `reset()` has somewhere to go. The header's meta now shrinks first (and ends in an ellipsis) so a label keeps about six characters at 320 px or large text. `grid.clock` and `widget.clock` still work and win for the element they are set on; read without one, they return the page clock's function, or `Date.now()`.
- A `<ts-table>` far down the page draws its first fit even before it is near the viewport, so a full-page screenshot or a find in the page no longer reads it with columns it has already measured to be too many.

- When a tile is under 7rem wide and its header meta ("just now", "synced 11:42", "stale 5 min") is dropped, the tile's `aria-description` and the dot's `title` carry that text, so neither the age nor the sync time is lost. It is read at each render, so a tile narrowed without a redraw catches up at its next one.

### Internal

- Deviation from RFC 0004 §11.2: `persistLayout` hears host assignments through a private `_watchLayout(fn)` hook on `<ts-grid>` (a layout can be assigned without any event), so a fake grid without it only misses the later captures. The grid also marks its own writes with `_persistWriting`, so its fallback layout for a device with nothing saved follows the host's latest layout and never a saved one. The `defaults` option of `persistLayout()` is still used first; a host assignment replaces it for that device from then on.
- Deviation from RFC 0004 §11.1: the RFC's model puts `width` on each resolved column; the model also resolves a table of only `'content'` columns to `'content'` for all but the last, which is `'fill'`, so the template never works it out. A fixed column's width is written through the CSSOM on its `<col>` and pinned on each of its cells (`min-inline-size` and `max-inline-size`), because a cell's own sizing lost to an unset text column and the column fell to the 56 px floor; the `<colgroup>` exists only while some column has a number. The `'content'` cap of half the table is a `calc(50cqi - 16px)` limit on the cell's text, as `max-inline-size` on a cell is not honoured in auto table layout.
- Deviation from RFC 0004 §11.3: the label already had `min-width: 0`, `overflow: hidden`, `white-space: nowrap` and an ellipsis (`.ell`); the story adds the `@container ts-tile (max-width: 11.25rem)` rule the RFC names (logical properties only) and the `title`. The unnamed-container rule that hides the meta text is unchanged. The container query measures the tile's content box, so it is in force for a tile about 218 px wide and under.
- Deviation from RFC 0004 §11.4: `now` for the widget and the grid reads `currentConfig().clock` at call time; the core exports no new function (`pageNow` is shared inside `format.js` and `calendar.js` only). `grid.clock` returns one stable function (`_pageClock`) when no own clock is set, so `grid.clock === grid.clock`.
- `widget.js` has one new private flag, `_drawOwed`, which lets a widget ask for a draw the viewport observer must not skip. `<ts-table>` sets it only until its first fit is settled (`_fitted`), so its first measured draws are not deferred to a scroll (the cause of the clipped P&L column in a full-page screenshot of the trading example at 390 px). Later fits follow the §23 rule as before.
- The trading example and the playground call `configure({ clock })` once instead of setting `clock` on the grid and on three tiles; their "Pretend it's" control calls it again after the offset changes. The fills table marks Instrument, Time and Side `'content'`, so at 390 px it keeps Instrument, Time and P&L (Qty fits at some font timings, and then four columns show) with no cell cut or scrolled.
- `test/browser/visual.spec.mjs`: the reload-until-the-columns-agree loop is gone. Ten loads of the trading example and of the widgets fixture on webkit, firefox and chromium, at 390 and 1280 px, each gave one column count (trading: 3 and 6; fixture tables: 3/4/4/4 and 3/6/6/6), so the loop is not needed; 61a95c2 holds.
- Tests: `test/table.test.mjs` (width resolution, the priority drop with and without widths at Tall, M and L, the `<col>` writes, the page clock on a widget), `test/persist.test.mjs` (both orders, both devices, the other device, the pending adapter load, the page clock on a grid), `test/format.test.mjs` (the `clock` option) and `test/browser/narrow.spec.mjs` (two Tall tiles at 390 px, headings at 150, 179 and 260 px, right-to-left, light and dark, the fills table at 390 and 1280 px).
