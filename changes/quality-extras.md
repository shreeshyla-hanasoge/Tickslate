### Internal

- Visual regression: `test/browser/visual.spec.mjs` screenshots every registered widget at every size it supports, in the light and dark themes, at a desktop (1280 x 800) and a phone (390 x 844) viewport, in the chromium project only, at `maxDiffPixelRatio` 0.001. Baselines live in `test/browser/visual.spec.mjs-snapshots/`. `npm run test:visual` compares; `npm run test:visual:update` rewrites them inside `mcr.microsoft.com/playwright:v1.64.0-noble` through Docker. A new `visual` CI job runs in that image and uploads the diff images on failure; `test/visual-pin.test.mjs` fails if the image tag and the pinned `@playwright/test` version drift apart. Making the job a required check is a repository setting.
- API snapshot: `test/api-surface.test.mjs` reads exports, each tag's observed attributes, events, `ts-action` names and parts, the `--ts-*` tokens and the `package.lib.json` entries by regular expression (no install) and fails on any difference from `test/api-surface.snapshot.json`; `npm run api:update` rewrites the snapshot.
- `docs/VERSIONING.md` states what counts as breaking for each surface.
- `npm run coverage` (`coverage:core`, `coverage:models`) runs the unit suite under Node's coverage and enforces 90 % lines for `src/core` and 80 % for `src/elements/*.js` without the DOM-bound infrastructure files. A new `coverage` CI job runs it on Node 22 (the flags need 20.17 or newer).
- Deviation from RFC 0004 §9.1: Docker was not available on the build machine, so the baselines committed here were generated locally on macOS (files named `*-chromium-darwin.png`), not in the container. They are not canonical. The first `visual` CI run on Linux finds no `*-linux.png`, writes them and fails; commit the `visual-baselines` artifact it uploads and delete the darwin files.
- Coverage measured on the 0.3.0 integration tree: `src/core` 99.82 % lines (threshold 90 met); the view models 77.5 % (threshold 80 NOT met). The thresholds are set as the RFC names them and not lowered, no filler tests were written and nothing was fenced out. Because `npm run coverage` therefore exits non-zero today, the `coverage` CI job is report-only (`continue-on-error: true`) until the follow-ups below pass; then delete that line. Files under 90 %: `src/elements/html.js` 56.1 %, `src/elements/layout-list.js` 37.7 %, `src/elements/pnl-calendar.js` 68.7 %, `src/elements/progress.js` 85.5 %. The maintainer decides whether to add tests or to add html.js and layout-list.js to the DOM-bound exclude list.
- The 0.3.0 tree's `npm run release` currently fails `npm run size` on per-entry budgets that the integrated stories exceeded (card, metric, table, watchlist, open-positions and others); this story changes no source and raises none.
